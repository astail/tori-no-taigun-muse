# セキュリティ方針

公開リポジトリ／公開サイトであることを前提に、以下を守ります。

## サイト側
- **秘密情報を一切含めない**：APIキー、トークン、パスワード等は
  リポジトリにもサイトにも置きません。ビルドも不要な静的ファイルのみで構成します。
- **外部リソースを読み込まない**：外部フォント・CDN・解析タグ・広告は不使用。
  これによりサプライチェーン汚染とトラッキングの両方を避けます。
- **Content-Security-Policy** を `<meta>` で付与：
  `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'none'` など。
  インラインスクリプト／インラインスタイルも使っていません。
- **データ収集なし**：スコア等はメモリ上のみで保持し、サーバー送信・
  ローカルストレージ保存をしません。ページ更新で消えます。
- **X共有リンク**：`target="_blank"` には `rel="noopener noreferrer"` を付け、
  共有テキストとURLは `encodeURIComponent` でエンコードします（文字列注入防止）。
- **DOM操作**：ユーザー由来の文字列を `innerHTML` に入れません（`textContent` を使用）。
- 入力は `pointerdown` / Space のみ。フォーム送信や外部POSTは存在しません。

## リポジトリ／CI側
- GitHub Actions のワークフローには最小権限を明示します
  （CI: `contents: read` のみ。Pages: デプロイに必要な権限のみ）。
- CI はテスト実行のみで、シークレットを参照しません。
- 依存パッケージは **ゼロ**（Node.js 標準のテストランナーを使用）。
  依存が無いため、脆弱性のある依存が混入する経路がありません。
- Dockerfile は静的ファイルの配信用で、コンテナ内でも秘密情報を持ちません。

## 脆弱性を見つけた場合
- 公開 Issue で詳細を晒さず、まずリポジトリ所有者へ非公開で連絡してください。
